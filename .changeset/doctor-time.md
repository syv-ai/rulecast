`rulecast doctor --time` reports whether tool-backed rules fit in the stop check's time budget (#83). It runs each rule whose detector runs a tool (a hook, a command, a linter) once, over every file the rule matches, which is the most an agent's stop can hand it. A new `timing` section reports its wall time against `timeouts.verify_ms`, for example `mypy-check — 41.2 s of 60.0 s on 928 files`. A stop runs all its rules in one budget, hooks one after another, so a last line runs them all together the way a stop does (`rulecast run --all-files`, llm rules left out): two rules that each fit can be cut off together. A rule or set of rules over the budget is a warning, which suggests raising `timeouts.verify_ms`, or switching the rule off and running the tool from a git hook or CI job of its own. A rule whose tool is missing, or whose dry run failed, is said once above and not timed. Before, a whole-project type checker or test suite had to be turned on before you found out it was too slow. In-process detectors (regex, ast-grep) take milliseconds and `llm` rules cost money per run, so neither is timed alone. `SETUP.md` has the agent run it after setup.

A tool rulecast runs now gets a process group of its own, and a deadline ends the whole group. Before, only the tool itself was killed: a pre-commit hook's formatter kept running past the deadline and rewrote the files after rulecast had put them back. Ctrl-C, SIGTERM or SIGHUP to rulecast ends the tools it is running. A process that left the group but still holds the tool's output no longer keeps rulecast waiting past the deadline. Ctrl-C during `doctor` ends the running tools, puts back what a formatter hook changed, and exits 130.

`doctor`'s touch-context section divides the message the way the hook does when other configs above a file also send touch context for it. Before, it measured each config against the whole message, said it fitted, and the hook then cut both.
