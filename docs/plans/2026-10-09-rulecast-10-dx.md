# rulecast Plan 10 — Developer Experience Implementation Plan

> **For agentic workers:** Use the executing-plans skill to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The same rule reports the same line the same way in an agent hook, a git hook and CI. A team gets from `init` to a firing hook without a trap. The agent is told what to do with what it receives, and cannot quietly edit its way past the gate. A rule author can see what is configured and gets messages that say what to do.

**Approach:** Every finding of the DX review of 2026-10-09 (the "rulecast DX review" doc), each reproduced on the published 0.3.0 and confirmed unchanged on `main`. Tasks 1–6 make `rulecast run` correct as a git hook: one owner for where a file's content comes from, staged mode with a HEAD baseline reading the index, and the messages a hook author sees. Task 7 adds suppression. Tasks 8–11 are about the agent. Tasks 12–14 are adoption. Tasks 15–18 are the rule author. Tasks 19–22 ship it: docs, the git-hook integrations, rulecast on its own repository, the unscoped npm name.

**Stack:** Node ≥ 20.12, TypeScript 5, zod 3, vitest.

Prerequisite: plan 9 is done (Task 11 stays blocked on PR #7 and is not part of this plan).

## Decisions this plan implements

Decided by the user on 2026-10-09, after the review:

1. **Staged mode reads the index, judged against HEAD.** `rulecast run` with no file flags checks staged files, reads their content from the index, and classifies against `HEAD` — the same "new means on a line you changed" as the agent hook. A repository with no commits yet has no baseline: every finding is new, as today.
2. **`--to-ref B` reads content at B.** Pre-push and CI judge what is being pushed, not the working tree. `--from-ref A` without `--to-ref` keeps reading the working tree (it includes uncommitted work on purpose).
3. **Detectors that hand a path to another program are given the staged content, under the real path where the tool allows it.** *Amended in review:* a scratch copy at `<root>/.rulecast-staged-XXXX/<path>` breaks configuration keyed on paths. eslint flat-config `files:` globs stop matching (a silent pass), ruff `per-file-ignores` stop matching, nested `pyproject.toml` files are missing, and typescript-eslint `parserOptions.project` rejects the file. So:
   - A detector that can be handed content under the file's real path declares `takesContent(config): boolean` and is run with `fromDisk: false`; it reads through `read` and pipes the text to its tool. `linter` declares it for ruff (`--stdin-filename`) and eslint (`--stdin --stdin-filename`). oxlint gets it only if Task 2 verifies a stdin mode.
   - `llm` declares it unconditionally: it sends text to a model and never needed the disk.
   - Everything else (`command`, oxlint without stdin) gets a scratch copy inside the project root, as `rulecast test` does for examples, with findings mapped back. The spec and README state the limitation: a `command` script sees a scratch path in staged and `--to-ref` runs.
4. **Suppression is both a rule switch and an inline ignore.** `enabled: false` on any rule, catalog rules included. `rulecast-ignore: <rule-id> <reason>` on the matched line or the line above, in whatever comment syntax the file uses; the reason is required. Ignores added during an agent session are reported to the user at Stop, and `run --summary` counts them.
5. **Staged mode skips metered detectors unless `--llm`.** One line says what was skipped. `--all-files`, `--from-ref` and the agent's Stop are unchanged. `--no-llm` stays and means "skip metered detectors" everywhere.
6. **The unscoped npm name `rulecast` is claimed** with a forwarding package the user publishes.

Decided in planning:

7. **No `rulecast install` for git hooks.** lefthook, husky and pre-commit own `.git/hooks`; a third writer would fight them. rulecast ships a `.pre-commit-hooks.yaml` and documented recipes instead.
8. **`--files` keeps no baseline.** H1 was measured with `run --files` under the pre-commit framework. Only the shipped hook (Task 20, `pass_filenames: false`, staged mode) is fixed; `--files` stays an ad hoc "judge these files whole" mode, and the README says to use the shipped hook.
9. **The pre-commit hook is `language: system` calling the project's own install.** `language: node` would `npm install` this repository's pnpm workspace root, which fails on `workspace:` ranges and runs `prepare: lefthook install`. More importantly, the agent hooks already require `@syv-ai/rulecast` in the project's devDependencies, so the git hook runs the same version as the agent hook — one story, one version. `entry: npx --no-install rulecast run`.
10. **What the user must hear goes to the user.** A new `Delivery.notices: string[]` carries what an agent must not be the only one to see: the config changed this session, ignores added this session. The Claude Code adapter prints notices and rule warnings as `systemMessage`, never as model context. `--format agent` (agents without hooks) still prints warnings, because there is no one else to show them to.
11. **The config-change check rides on the baseline's `start` record.** It already marks the session's first event; it gains `configHash` (sha256 of `.rulecast-config.yaml`'s bytes). Old stores without the field get no notice.
12. **A missing binary is a no-op with one message.** The hook command becomes a shell guard: when `node_modules/.bin/rulecast` is absent it exits 0, and the `SessionStart` hook alone prints a `systemMessage` saying rulecast is configured but not installed. `install` rewrites rulecast's own entries whose command is stale (an entry it owns is not "an existing entry" in §12's sense).
13. **`init` preselects every adapter when no agent is detected**, interactively and under `--yes`, and the Review step says plainly when no hooks will be installed. With one adapter, preselecting it is the only default that does something.
14. **`init` preselects the detected doc heading that matches the package doc**, by shared words between the package doc's file name and section heading and the detected heading. No match keeps "keep the package's doc".
15. **`DRAFT-RULES.md` may override only `context` on a catalog rule.** Everything else under a URL repo stays forbidden.
16. **`rulecast list`** prints every configured rule: id, source, enabled, stages, detector kind, severity, `files`, context refs. `--format json` too.
17. **G3 is verified before it is fixed.** If a live session confirms a permission prompt, overflow files move to `.rulecast/overflow/` in the project, a directory that ignores itself (`.rulecast/.gitignore` containing `*`).

## Conventions

- The repository is a pnpm workspace; the CLI package lives in `packages/rulecast/`. Run commands from the repository root.
- Run one test file with `pnpm vitest run <path>`; the path is relative to `packages/rulecast/`. Run everything with `pnpm test` and types with `pnpm typecheck`.
- No module-level mutable state in `src/`. Detectors that declare `guards` read only through `read` (`docs/conventions.md`).
- A rule key is four changes (`docs/conventions.md`): Task 7's `enabled` touches schema, compile, spec §4 and `rule-format.md`, and `pnpm manifest`.
- The renderer prices its own output (`docs/conventions.md`): Task 9's wording changes go through the constants `deliveryCost` already prices; never copy a rendered string into `decide.ts`.
- Goldens change on purpose in Tasks 8, 9 and 11. A golden that changes in any other task is a finding.
- `pnpm perf` before Task 1 and after Tasks 1, 7 and 8: they touch the hook path. Compare against the parent commit back to back on the same machine (plan 9, "On reading `pnpm perf`").
- `pnpm test:linux` before pushing Tasks 1, 2, 13 and 21: they touch git, the filesystem, scratch directories and shell commands.
- lefthook runs biome and `pnpm typecheck` on commit, `pnpm test` on push. Never bypass them.
- Stage by exact path, then a plain `git commit`. Never `git add -A`, stash, reset or checkout.
- Commit after every task, straight to `main`. Messages end with a blank line and `Via [syv-ai/dash](https://github.com/syv-ai/dash)`.
- **When a planned test fails, find the cause before changing the test.**
