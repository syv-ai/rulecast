rulecast checks your agent's edits as it makes them, and tells it about a broken rule in the same turn.

## Where it sits

rulecast runs as your agent's hooks. Each tool call the agent makes passes through it on the way out, on the way back, or both.

A run with nobody watching, such as a CI job or `/goal`, can hold the agent more often: [Agent loops](/rulecast/guides/agent-loops/) says how.

## What gets written

Setup writes three files, which you commit:

- `.rulecast-config.yaml`: your rules.
- `.claude/settings.json`: Claude Code's hook entries. Each one runs the script below. With `--scope personal` they go in `.claude/settings.local.json` instead, which is not committed.
- `.claude/hooks/rulecast.sh`: finds a rulecast to run. It tries the project's `node_modules/.bin/rulecast`, then `rulecast` on the PATH, then the directory `install.sh` installs to (`$RULECAST_INSTALL_DIR`, else `$XDG_BIN_HOME`, else `~/.local/bin`), for an agent started from the Dock or an IDE whose PATH may lack it. With none, it does nothing and says so when a session starts. It never downloads or installs anything.
